### Standalone Express/MySQL

For a standalone MySQL installation, apply `server/migrations/202611090001_news_alumni.sql` to its selected application database before using News/Alumni. It creates only the two new tables and can be reapplied. Fresh databases get those tables from `server/schema.sql`. Keep the earlier Statistics publication prerequisite from `ADMIN_QA.md` if that migration is still missing.

Supabase uses database timestamp triggers. Express/MySQL stamps publication time in the API and stores it as UTC. Calendar dates and public date display use Asia/Manila.

## API and data contracts

- Supabase tables: `cms_updates` and `cms_alumni`. Authenticated non-admins receive only published public content; only allowlisted admins can write.
- Public Express reads: `GET /api/updates`, `GET /api/updates/:id`, `GET /api/alumni`, `GET /api/alumni/batches`.
- Admin Express reads/CRUD: `GET/POST /api/admin/{updates|alumni}`, `GET/PUT/DELETE /api/admin/{updates|alumni}/:id`.
- Lists return `{ items, total, page, pageSize }`; page size is bounded to 12, with smaller homepage previews. Updates filter by `category`; alumni filter by `batch`.
- List responses exclude article bodies. Direct public detail reads of a draft/deleted update return not-found. Supabase access errors never switch to a local store.
- News fields: title, category (`news`, `event`, `announcement`), summary, cover image URL, structured `body_json`, publication state and timestamps. Alumni fields: name, image URL, batch, company, position, display order, publication state and timestamps.
- History and Why Choose use the existing `site_settings` mechanism; they do not replace branch or reservation data.
